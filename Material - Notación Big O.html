Material - Notación Big O

El estándar mundial para medir la velocidad, eficiencia y escalamiento de algoritmos y estructuras de datos sin depender de qué computadora tengas.

¿Por qué es el tema más importante de la materia?

Cuando un programa procesa 10 datos, casi cualquier algoritmo responde en menos de 1 milisegundo. Pero cuando procesa 100.000 o 10.000.000 de registros, un mal algoritmo puede tardar días enteros o agotar la memoria RAM del servidor.

La Notación Big O te da ojos de rayos X para predecir si tu código resistirá el mundo real.

1. Es Universal

No mide segundos de reloj. Mide cómo crecen los pasos matemáticos cuando la entrada crece.

2. Explica las Estructuras

Explica por qué un vector es $O(1)$ en acceso pero $O(N)$ al insertar al inicio, o por qué una búsqueda binaria es $O(\log N)$.

3. Clave en Evaluaciones

En parciales y entrevistas de programación es obligatorio justificar la complejidad temporal y espacial.

Avanza con las flechas del teclado o los botones inferiores.

¿Por qué no medimos el tiempo con un cronómetro?

Si mides un programa con reloj (chrono en C++), el resultado depende de si corres en un iPhone, en una laptop vieja o si abriste YouTube de fondo. Necesitamos una medida matemática objetiva.

El Problema de Medir Segundos

Imagina que ejecutas dos algoritmos y mides el tiempo en tu PC:

  • El procesador tiene núcleos diferentes y frecuencias variables (GHz).
  • La memoria RAM y el sistema operativo pueden estar ocupados en segundo plano.
  • El compilador puede aplicar optimizaciones impredecibles.

Conclusión: Los segundos no permiten comparar algoritmos de forma científica.

La Solución: Contar Operaciones Fundamentales

En vez de mirar el reloj, contamos cuántas operaciones elementales (comparaciones, sumas, asignaciones) hace el código en función de $N$ (la cantidad de datos):

// Ejemplo: ¿Cuántos pasos hace este bucle?
for (int i = 0; i < N; i++) {
    cout << arr[i]; // Se repite exactamente N veces
}
// Con N = 100   -> 100 operaciones
// Con N = 10000 -> 10000 operaciones
// Complejidad: O(N) (Crecimiento lineal)

La Trinidad Asintótica (O, Ω, Θ)

O (Big O)

Peor caso (Límite Superior): El techo máximo de pasos que dará el algoritmo. Es el que nos importa en ingeniería para garantizar que el sistema no colapse.

Ω (Omega)

Mejor caso (Límite Inferior): El escenario más afortunado. Por ejemplo, en búsqueda lineal, encontrar el elemento en la primera posición ($O(1)$).

Θ (Theta)

Caso Promedio / Ajustado: Describe el comportamiento típico cuando el mejor y peor caso crecen con el mismo orden de magnitud.

La Jerarquía de Complejidades (El Semáforo)

De la velocidad de la luz a lo computacionalmente imposible. Estas son las 7 familias más importantes:

O(1) — Constante

Excelente. El tiempo no cambia sin importar si hay 1 dato o 10.000.000. Ej: arr[5], pila.push().

O(log N) — Logarítmica

Muy rápida. En cada paso divide los datos a la mitad. Para 1 millón de datos hace solo 20 pasos. Ej: Búsqueda Binaria.

O(N) — Lineal

Aceptable. Si los datos se duplican, el tiempo se duplica. Un solo bucle for. Ej: Búsqueda Lineal, imprimir un vector.

O(N log N) — Linealítmica

Límite veloz de ordenamiento. El estándar de oro para ordenar datos en RAM. Ej: Quicksort, Mergesort, Shell Sort.

O(N²) — Cuadrática

Peligrosa. Bucles anidados. Con 1.000 datos hace 1 millón de pasos. No escala. Ej: Ordenamiento Burbuja.

O(2ᴺ) — Exponencial

Intratable. Cada nuevo elemento duplica el tiempo. Con $N=40$ tarda minutos, con $N=70$ tarda siglos. Ej: Fibonacci recursivo ingenuo.

O(N!) — Factorial

La peor de todas. Generar todas las permutaciones posibles. Con $N=20$ el universo terminaría antes de que finalice.

Regla nemotécnica de velocidad:

O(1) < O(log N) < O(N) < O(N log N) < O(N²) < O(2ᴺ) < O(N!)

Las 4 Reglas de Oro para Calcular Big O

Aprende a simplificar cualquier expresión algebraica a su Big O real en 4 pasos:

Regla 1: Desprecia las Constantes

No importa si un bucle hace $2N$, $5N$ o $100N$ operaciones; la tasa de crecimiento sigue siendo lineal ($O(N)$).

// Dos bucles consecutivos del mismo tamaño:
for(int i = 0; i < n; i++) { ... } // N pasos
for(int j = 0; j < n; j++) { ... } // N pasos
// Total: 2N -> Se simplifica a O(N)

Ignoramos los números multiplicadores: $O(3N^2) \rightarrow O(N^2)$.

Regla 2: Quedarse con el Término Dominante

Si tienes una función como $f(N) = N^2 + 500N + 10000$, para valores grandes de $N$ el término $N^2$ aplasta por completo a todos los demás.

Si N = 100,000:
N²     = 10,000,000,000 (Diez mil millones)
500N   = 50,000,000 (Cincuenta millones)
10000  = 10,000

// Resultado final: O(N²)

Regla 3: Bucles Consecutivos se Suman

Si los bucles están uno después del otro de manera independiente, sus costos se suman:

for(int i=0; i<A; i++) { ... } // O(A)
for(int j=0; j<B; j++) { ... } // O(B)

// Complejidad total: O(A + B)

Regla 4: Bucles Anidados se Multiplican

Si un bucle está dentro de otro, cada iteración exterior ejecuta el bucle interior completo:

for(int i=0; i<N; i++) {       // N veces
    for(int j=0; j<N; j++) {   // N veces
        // Se ejecuta N * N veces
    }
}
// Complejidad total: O(N * N) = O(N²)

Patrones Visuales en Código C++

Identifica la complejidad con solo mirar la estructura de control del código:

O(1)

Acceso Directo

int consultar(int arr[], int idx) {
    return arr[idx]; // 1 sola operacion
}
// No hay ciclos for ni while

Operaciones aritméticas, lecturas y asignaciones simples.

O(log N)

División Repetida (/= 2)

void partir(int n) {
    while (n > 1) {
        n = n / 2; // Divide a la mitad
    }
}
// i *= 2 o i /= 2 siempre es O(log N)

Búsqueda binaria, árboles equilibrados.

O(N)

Un Ciclo Simple (i++)

int sumar(int arr[], int n) {
    int total = 0;
    for(int i = 0; i < n; i++) {
        total += arr[i];
    }
    return total;
}

Recorrer un arreglo, encontrar el máximo.

O(N log N)

Un Ciclo N que contiene una División (/ 2)

for (int i = 0; i < n; i++) {       // Se ejecuta N veces
    for (int j = n; j > 0; j /= 2) { // Se ejecuta log(N) veces
        operacion();
    }
}
// Total: N * log(N) = O(N log N)

Quicksort, Mergesort (divide el array a la mitad recursivamente y en cada nivel procesa $N$ elementos).

O(N²)

Ciclos Anidados

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        comparar(arr[i], arr[j]);
    }
}
// Burbuja, comparar todos contra todos

Matrices $N \times N$, pares de elementos.

Complejidad Espacial (Memoria RAM)

Big O no es solo para el tiempo: mide también cuánta memoria RAM adicional necesita crear el algoritmo para ejecutarse.

Espacio O(1): Algoritmos In-Place

Solo usan unas pocas variables escalares auxiliares (índices, banderas, temporales). No importa si el arreglo tiene 10 o 10 millones de datos, la memoria extra es constante.

// Ejemplo: Invertir un array In-Place
void invertir(int arr[], int n) {
    int temp; // O(1) memoria extra
    for(int i = 0; i < n / 2; i++) {
        temp = arr[i];
        arr[i] = arr[n - 1 - i];
        arr[n - 1 - i] = temp;
    }
}
// Espacio auxiliar: O(1)

Burbuja, Shell Sort y Quicksort son ejemplos de memoria espacial muy baja.

Espacio O(N): Algoritmos Out-of-Place

Crean un segundo arreglo o copian la estructura en memoria RAM. Si tu entrada ocupa 2 GB, necesitarás otros 2 GB libres en el sistema.

// Ejemplo: Crear un clon temporal
void copiar(int original[], int n) {
    int* copia = new int[n]; // Pide N casillas en Heap
    for(int i = 0; i < n; i++) copia[i] = original[i];
    // ...
    delete[] copia;
}
// Espacio auxiliar: O(N)

Mergesort requiere memoria espacial $O(N)$ para mezclar las mitades temporales.

¡Cuidado con la Recursión! (El Call Stack)

Cada vez que una función se llama a sí misma, la computadora guarda los parámetros y variables locales en la Pila de Llamadas (Stack). Si una función recursiva baja $N$ niveles de profundidad, consumirá $O(N)$ de memoria espacial en el Stack, arriesgando un Stack Overflow.

Resumen y Mejores Prácticas

                
    
                    
  • Big O mide la tasa de crecimiento: Ignora los segundos de reloj y describe cómo escala el algoritmo cuando $N$ crece hacia el infinito.
    • 
                    
  • Regla de oro: Desprecia constantes numéricas ($O(3N) \rightarrow O(N)$) y conserva únicamente el término de mayor crecimiento ($O(N^2 + N) \rightarrow O(N^2)$).
    • 
                    
  • Para búsquedas: Búsqueda Lineal es $O(N)$ (desordenado). Si el arreglo está ordenado, usa Búsqueda Binaria para saltar a $O(\log N)$.
    • 
                    
  • Para ordenamiento: Burbuja ($O(N^2)$) es solo didáctico. En aplicaciones reales, Quicksort, Mergesort y Shell Sort operan en $O(N \log N)$.
    • 
                    
  • No olvides la memoria: Un algoritmo veloz que consuma $O(N)$ de memoria RAM puede agotar los recursos en sistemas con millones de registros.
